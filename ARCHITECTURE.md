# Presence Planner – architecture and contracts

This file is the contract between all parts of the project. Every module follows it. If a part needs a change here, it is proposed first, not silently implemented.

## What it is

A Home Assistant integration (HACS category `integration`, domain `presence_planner`) that plans presence and motion sensors on a floor plan:

- coverage per room, in 3D (mount height, tilt, horizontal and vertical field of view), shown at three heights: lying 0.5 m, sitting 0.9 m, standing 1.3 m
- "misfire risk": how much a sensor sees into rooms it does not belong to (through thin walls and open doors)
- suggestion of the best mount point per room or for all rooms
- a 2D planner with a rotatable 3D view next to it, a floor plan editor for users without NeonPlan 3D
- entities per room: coverage %, misfire risk %, and a cleaned occupancy binary sensor that drops known cross-room echoes
- English and German UI (follows `hass.language`)

Minimum Home Assistant: 2026.10. License MIT. No telemetry, no network calls.

## Coordinates and units

Metres. Plan view: `x` to the right, `z` down the plan (top of the drawing to the bottom). Height `y` up from the floor. Angles in degrees.

- `phi`: horizontal viewing direction in the plan, `0` = +x (right), `90` = +z (down), clockwise on screen, range 0–359.
- `tilt`: downward tilt from horizontal, `0` = level, `90` = looking straight down (ceiling mount).

## Plan schema `pp-plan` (version 1)

A subset of the NeonPlan 3D building format, so the NeonPlan adapter is a near pass-through and the editor can export the NeonPlan import format.

```json
{
  "version": 1,
  "settings": { "wall_exterior": 0.24, "wall_interior": 0.12 },
  "floors": [{
    "id": "f1", "name": "Ground floor", "ha_floor": "erdgeschoss", "elevation": 0, "height": 2.6,
    "rooms": [{ "id": "living", "name": "Living room", "area_id": "living_room",
                "points": [[0, 0], [5, 0], [5, 4.2], [0, 4.2]],
                "wall_thickness": [0.3, 0.115, 0.115, 0.3], "ceiling_height": null }],
    "openings": [{ "id": "d1", "room_id": "hall", "edge": 0, "offset": 1.0, "width": 0.9,
                   "type": "door", "sill": 0, "height": 2.0, "hinge": "left", "swing": "in",
                   "contact": "binary_sensor.living_door" }],
    "walls": [{ "id": "chimney", "a": [1.0, 6.6], "b": [1.6, 6.6], "thickness": 0.4, "height": null }],
    "furniture": [{ "id": "bed1", "type": "bed", "x": 6.8, "z": 1.2, "w": 1.6, "d": 2.0, "h": 0.5, "rotation": 0 }],
    "outdoor": [],
    "background": null
  }]
}
```

Wall rule (same as NeonPlan): an edge shared by two rooms is an interior wall drawn centred on the edge; an edge with no neighbour room is an exterior wall drawn fully outside the polygon. Edges are split at vertices of other rooms that lie on them. `wall_thickness[i]` belongs to edge `i` (point `i` to `i+1`); missing → `settings.wall_exterior` / `wall_interior`; a shared wall takes the larger value of both rooms. `wall_heights[i] == 0` means no wall on that edge.

Openings: `edge` and `offset` refer to the room edge; `offset` is the opening centre measured from the edge start. `hinge: "right"` = hinge at the end side of the edge, `"left"` = start side. `swing: "in"` = into `room_id`. `contact` (optional) = a binary sensor that is `on` while the door is open.

Furniture: `rotation` clockwise in degrees, `w` along the front, `d` depth. Footprint corner `(a, b)` in local coordinates maps to `(x + a·cos r − b·sin r, z + a·sin r + b·cos r)`.

`background` (editor only): `{ "image": "<data URL>", "x": 0, "z": 0, "width": 8.0, "rotation": 0, "opacity": 0.5 }`. The image is stored inline as a data URL, so it lives in the integration's store together with the plan.

## Sensor record `pp-sensor`

```json
{ "entity_id": "binary_sensor.kitchen_presence", "floor_id": "f1",
  "x": 4.6, "z": 3.9, "height": 1.9, "phi": 235, "tilt": 10, "mount": "wall",
  "profile": "aqara_fp300", "fov_h": 120, "fov_v": 90, "reach": 6.0, "active": true }
```

`mount`: `wall` | `corner` | `ceiling`. `fov_h`, `fov_v`, `reach` start from the profile and may be overridden. `active: false` keeps a sensor out of the calculation.

NeonPlan mapping (when NeonPlan is the plan source): placement `x`, `z`, `y` = `height`, `rotation = (phi − 90) mod 360`, `tilt` = `tilt`, `fov` = `fov_h`, `reach` = `reach`. `profile`, `mount`, `fov_v` live in the presence_planner store, keyed by `entity_id`. Only those NeonPlan fields are ever written.

## Sensor profiles `shared/profiles.json`

List of `{ id, name, manufacturer, match: [lowercase substrings matched against "manufacturer model name" of the HA device], tech: "mmwave"|"pir"|"hybrid", fov_h, fov_v (null = unknown → 90 is used and flagged), reach, reach_static (null = same as reach), mounts: [...], ceiling: { fov, reach } | null, verified: bool, source: url, note }`. `custom` is always present.

## Model (identical in `core/` Python and `frontend/src/core/` JS)

Inputs: one floor of a `pp-plan`, the floor's `pp-sensor` list, options `{ heights: [0.5, 0.9, 1.3], doors: "open" | "closed" | {door_id: bool}, thin_db: 10, cell: 0.1 }`.

### Build step `build_model(plan, floor_id)`

- wall segments after the split, each with `thickness`, `shared` flag, inward normal per room
- attenuation category per wall segment: `block` (exterior, or thickness ≥ 0.20, or free wall with height null or ≥ 1.5 m), `brick` (0.10 ≤ t < 0.20 → 25 dB), `thin` (t < 0.10 → `thin_db`)
- doors: the door span is cut out of its wall segment and kept as a door segment (open: 0 dB, closed: 6 dB). Windows in exterior walls stay `block` and are listed as glass (for the glass warning). Doors in exterior walls lead outside and are ignored for spill.
- furniture with `h ≥ 1.5` that is not a lamp, `led_strip`, `shower`, `plant`, `rug`, `coat_rack` is an obstacle: a ray is damped by 10 dB if, where it crosses the footprint, its height is below `h`
- cells: grid with spacing `cell` over each room polygon, excluding points inside wall bands and free walls
- zones from furniture: `bed`/`bunk_bed` (footprint, "bed"), `sofa*`/`armchair` (footprint, "sofa"), `desk` (+0.5 m), `table*` (+0.45 m, "dining"), `kitchen`/`worktop`/`sink`/`stove` (+0.6 m ring without the footprint, "kitchen"), `wc` (+0.3 m), `shower`, `bathtub`, `washbasin` (+0.5 m ring). Entry zones: cells within 0.9 m of each door centre, on both sides.

### Detection `detect(sensor, point3d)` → quality 0…1

- `v = p − s` in 3D (`s = (x, height, z)`).
- Wall/corner mount: forward `f = (cos φ·cos τ, −sin τ, sin φ·cos τ)` with φ = phi, τ = tilt (y up). Right `r = normalize(f × up)`, up' `u = r × f`. `yaw = atan2(v·r, v·f)`, `pitch = atan2(v·u, hypot(v·f, v·r))`. Inside if `v·f > 0`, `|yaw| ≤ fov_h/2`, `|pitch| ≤ fov_v/2`.
- Ceiling mount: forward = straight down; inside if the angle between `v` and down `≤ ceiling.fov/2` (fallback `max(fov_h, fov_v)/2`).
- Edge taper: `g = (1 − 0.4·clamp((|yaw| − (fov_h/2 − 15))/15, 0, 1)) · (1 − 0.4·clamp((|pitch| − (fov_v/2 − 10))/10, 0, 1))`; ceiling uses the yaw formula on the cone angle.
- Attenuation `L` (dB) along the 2D segment from sensor to point: `block` → not detected; `brick` +25; `thin` +`thin_db`; closed door +6; obstacle +10.
- Detected if `|v| ≤ reach · g · 10^(−L/20)`.
- Quality: `1` for `|v| ≤ 0.58·reach`, then linear down to `0.6` at `reach`.

### Results `evaluate(model, sensors, opts)`

Per room and per height: `coverage` = mean over cells of the best quality from sensors **located in that room**; `seen` = share of cells with quality > 0. Per room: `misfire_risk` = share of the room's cells at 1.3 m seen by at least one sensor located elsewhere (worst case: doors open). Per sensor and foreign room: `spill_share`. Per zone: share of zone cells seen at the zone height (bed 0.5, sofa/desk/dining/wc 0.9, others 1.3). A sensor is located in the room whose polygon contains `(x, z)`.

### Spill detail `spill_detail(model, sensor)`

For each foreign room: `{ "total": share, "walls": share, "doors": { door_id: share } }` – each spill cell is classified by the door opening its ray passes through (or "walls" if none). Used by the cleaned occupancy.

### Optimizer `optimize(model, room_id, profile, opts, weight)`

Candidates: wall points every 0.1 m (3 cm in front of the wall face, not on doors, windows or tall furniture), corners, and for ceiling-capable profiles a 0.5 m ceiling grid. Directions: wall normal ±70° in 10° steps, then refine ±5°. Mount height and tilt from the profile default (wall 1.9 m, tilt 10°; ceiling = room height, tilt 90°). Score = room coverage (zones weighted ×3, entry zones ×2) − `weight` · spill (flur/hall-type rooms count ×3) − 0.3 · glass facing. `weight` comes from the UI slider (0 = only coverage, 2 = strongly avoid misfires, default 1). Returns the best 5 distinct candidates.

The JS core must reproduce the golden results within 2 percentage points for shares and 0.05 m / 5° for optimizer results.

## Integration (Python, `custom_components/presence_planner/`)

- Config flow, one entry. Options: plan source (`auto` → NeonPlan if loaded, else own plan; `neonplan`; `own`), `thin_db`, `hold_time` (s, default 30), `echo_window` (s, default 5), `spill_threshold` (default 0.05).
- Store `.storage/presence_planner`: `{ "plan": pp-plan | null, "sensors": { entity_id: {profile, mount, fov_v, ... own fields} }, "own_sensors": [pp-sensor] }`.
- NeonPlan adapter: reads and writes through NeonPlan's own runtime data object and listens to its change signal (inspect github.com/Mastershort/neonplan3d `storage.py`, `websocket.py`). Version-guarded; if NeonPlan changes its internals, the adapter reports `neonplan_incompatible` and the integration falls back to the own plan instead of crashing.
- WebSocket commands (all need auth, writes need admin):
  - `presence_planner/get` → `{ source, revision, plan, sensors: [pp-sensor], profiles, options, neonplan: {installed, version, linked} }`
  - `presence_planner/subscribe` → events `{ revision }` on plan or sensor changes
  - `presence_planner/save_sensors` `{ sensors: [pp-sensor] }` → writes NeonPlan fields or own store
  - `presence_planner/save_plan` `{ plan }` → own plan only
  - `presence_planner/export` → NeonPlan import format (`format: "neonplan-import"`, `rooms_at: "centre"`)
  - `presence_planner/import` `{ data }` → own plan from NeonPlan import format or a NeonPlan building
  - `presence_planner/link_neonplan` → adds a NeonPlan menu button `{id: "presence_planner", label, icon: "radar", action: "navigate", target: "/presence-planner"}`; only on this explicit call
  - `presence_planner/device_profiles` → suggested profile per sensor entity from the device registry
- Panel: sidebar entry "Presence Planner" at `/presence-planner`, web component `presence-planner-panel`, bundle served from `custom_components/presence_planner/frontend/`.
- Entities per room (has_entity_name, translation keys, unique_id `{entry_id}_{floor_id}_{room_id}_{key}`): `sensor` coverage % (mean over the three heights), `sensor` misfire risk %, `binary_sensor` occupancy (cleaned). Attributes carry per-height values. Recomputed in an executor on plan or sensor changes; door contacts only affect the cleaned occupancy.

### Cleaned occupancy (per room R)

- Own sensors of R: active plan sensors located in R. Their HA states are the inputs.
- For each own sensor `s` and neighbour room `N` with `spill_detail(s)[N].total ≥ spill_threshold`: an `on` of `s` is an **echo candidate** while a sensor `t` located in N is `on`, `t` turned on before `s`, `s` turned on within `echo_window` after `t` (a `t` that has been on for longer does not make `s` an echo: a second person, not a reflection), and every door through which `s` sees N is open or has no contact (a closed door with a contact removes that door's share; if the remaining share is below the threshold, `s` cannot echo into N).
- R is occupied if at least one own sensor is `on` and not an echo candidate. An echo candidate becomes valid as soon as all its `t` sensors are `off`.
- After the last valid `on` ends, R stays occupied for `hold_time`.
- Attributes: `sources`, `suppressed_echoes`, `last_valid_sensor`. Fully unit-tested with a fake clock.

## Frontend (`frontend/src/`)

Built with esbuild into `custom_components/presence_planner/frontend/presence-planner-panel.js` (ES module) and `presence-planner-worker.js` (optimizer in a Web Worker). Lit for components, three.js for 3D, no CDN. Theme from HA CSS variables (`--primary-text-color`, `--card-background-color`, `--divider-color`, `--primary-color`, `--error-color`), dark mode from `hass.themes.darkMode`. Strings from `i18n/{en,de}.json` by `hass.language`, fallback English.

Component boundaries:
- `panel/` owns state (plan, sensors, options, selection, dirty flag), talks to `api/`, runs `core/` for the 2D map and stats, hosts `<pp-view3d>` and `<pp-editor>`.
- `view3d/` exports `<pp-view3d>` with properties `model` (from `core.buildModel`), `sensors`, `evaluation` (from `core.evaluate`), `height` (0.5|0.9|1.3), `selected`, `dark`; emits `select` with an entity_id. Rendering only, no state.
- `editor/` exports `<pp-editor>` with property `plan` (pp-plan) and `floorId`; emits `plan-changed` with the new pp-plan. Tools: draw room polygon, move/insert/delete corner, wall thickness per edge, door, window, free wall, furniture rectangle, background image (upload as data URL into the store), assign HA area and floor, undo/redo.
- `core/` exports `buildModel, buildCells, detect, evaluate, spillDetail, optimize, PROFILES` with the same semantics as Python.

## Exact core API (Python and JS use the same names in their language style)

Python (`custom_components/presence_planner/core/__init__.py` re-exports):

```python
load_profiles() -> dict                      # parsed shared/profiles.json (bundled copy at core/profiles.json, kept identical by a test)
resolve_sensor(sensor: dict, profiles: dict) -> dict   # fills fov_h, fov_v, reach, mount defaults from the profile; fov_v None → profiles["default_fov_v"], adds "fov_v_assumed": True
build_model(plan: dict, floor_id: str) -> Model        # Model is a dataclass; plain lists/dicts inside, JSON-serialisable via model_to_dict()
detect(model: Model, sensor: dict, point: tuple[float, float, float], opts: dict) -> float   # point = (x, y, z), y = height
evaluate(model: Model, sensors: list[dict], opts: dict) -> dict
spill_detail(model: Model, sensor: dict, opts: dict) -> dict
optimize(model: Model, room_id: str, profile_id: str, opts: dict, weight: float = 1.0, profiles: dict | None = None) -> list[dict]
```

Default opts: `{"heights": [0.5, 0.9, 1.3], "doors": "open", "thin_db": 10, "cell": 0.1}`.

`evaluate` returns:

```json
{
  "rooms": { "<room_id>": {
      "coverage": { "0.5": 0.0, "0.9": 0.0, "1.3": 0.0 }, "coverage_mean": 0.0,
      "seen": { "0.5": 0.0, "0.9": 0.0, "1.3": 0.0 },
      "misfire_risk": 0.0,
      "from": { "<entity_id>": 0.0 },
      "own_sensors": ["<entity_id>"] } },
  "sensors": { "<entity_id>": { "room": "<room_id or null>", "glass": 0.0, "spill": { "<room_id>": 0.0 } } },
  "zones": [ { "name": "bed", "room": "<room_id>", "height": 0.5, "share": 0.0 } ],
  "grid": { "1.3": [ { "x": 0.0, "z": 0.0, "room": "<room_id>", "own": 0.0, "own_sensor": "<entity_id or null>", "spill": ["<entity_id>"] } ] }
}
```

`grid` is only filled when `opts["grid"]` is true (the panel asks for it, the integration does not). Shares are 0…1 rounded to 4 decimals. `from` and `spill` measured at 1.3 m.

`spill_detail` returns `{ "<foreign_room_id>": { "total": 0.0, "walls": 0.0, "doors": { "<door_id>": 0.0 } } }` at 1.3 m.

`optimize` returns up to 5 `{ "x", "z", "height", "phi", "tilt", "mount", "score", "coverage", "spill": { "<room_id>": share }, "glass" }`, best first.

JS (`frontend/src/core/index.js`): `PROFILES, resolveSensor, buildModel, detect, evaluate, spillDetail, optimize` with identical semantics, camelCase names, same JSON keys in results (snake_case keys as above). `buildModel` returns a plain object that also carries drawing data for the panel and the 3D view:

```js
{ floor: {id, name, height}, rooms: [{id, name, area_id, points, height}], bands: [[x,z]...][] , faces: [{a, b, n, room}],
  segments: [{a, b, k: "block"|"brick"|"thin"}], doors: [{id, a, b, hinge, tip, other, w, rooms: [id], contact, outside}],
  windows: [{id, a, b, n, exterior}], glass: [{a, b, n}], freeWalls: [{poly, height, block}],
  furniture: [{id, type, poly, h, obstacle}], zones: [{name, room, height, outer, inner}], cells: {"0.1": [...], "0.2": [...]},
  bounds: {x0, x1, z0, z1} }
```

Golden files written by `python -m custom_components.presence_planner.core.golden` into `shared/golden/`: `demo-detect.json` (≥ 300 sensor/point samples with expected quality), `demo-evaluate.json` (evaluate on the demo plan, doors open and doors closed, without grid), `demo-spill.json`, `demo-optimize.json` (best candidate per room for `aqara_fp300`, weight 1, cell 0.2 to keep it fast).
